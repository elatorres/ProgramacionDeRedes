# C# RabbitMQ Asynchronous Request/Response Example

This example demonstrates an asynchronous request/response pattern using RabbitMQ in C#.
A client sends a request to a server and does not block waiting for the response. Instead, it receives a `Task<ResponseMessage>` which it can await later after performing other operations. The server processes the request and sends the response back to a specific reply queue listened to by the client.

## Core Concepts Demonstrated
- Asynchronous client-side request (`async/await` with `Task`).
- RabbitMQ for message queuing.
- Request/Reply pattern (RPC style).
- `CorrelationId` for matching requests with responses.
- `ReplyTo` property for specifying the return address for the response.
- `TaskCompletionSource` for bridging callback-based message consumption with `Task`-based asynchronous programming.

## Prerequisites
- .NET SDK (e.g., .NET 10.0 or newer recommended).
- A running RabbitMQ instance. For local development, you can use Docker:
  `docker run -d --hostname my-rabbit --name some-rabbit -p 5672:5672 -p 15672:15672 rabbitmq:management`
  (Access management UI at `http://localhost:15672` with guest/guest).

## Setup & Running

1.  **Clone/Download the Code:**
    Get the code onto your local machine.

2.  **Restore Dependencies:**
    Navigate to the `RabbitMqAsyncExample/RabbitMqClient` and `RabbitMqAsyncExample/RabbitMqServer` directories respectively and run:
    ```bash
    dotnet restore
    ```
    This will install the `RabbitMQ.Client` package. The code uses `System.Text.Json` for JSON serialization, which is included in modern .NET SDKs. If you are using an older .NET Framework or .NET Core version, you might need to add a NuGet package reference for it.

3.  **Run the Server:**
    Open a terminal, navigate to `RabbitMqAsyncExample/RabbitMqServer` and run:
    ```bash
    dotnet run
    ```
    The server will start and print messages like: `[Server] Received request...`, `[Server] Sent response...`, and `[x] Server awaiting requests`.

4.  **Run the Client:**
    Open another terminal, navigate to `RabbitMqAsyncExample/RabbitMqClient` and run:
    ```bash
    dotnet run
    ```
    The client will send a few requests, simulate other work, and then print the responses as they are received.

## Asynchronous Flow Explanation

1.  **Client Initialization (`RabbitMqRpcClient` constructor):**
    *   Connects to RabbitMQ.
    *   Creates an exclusive, auto-delete **reply queue**. This queue is unique to this client instance and is where the server will send responses. Its name is generated by RabbitMQ (e.g., `amq.gen-...`).
    *   Starts a consumer on this reply queue.

2.  **Sending a Request (`SendRequestAsync`):**
    *   A unique `CorrelationId` (a GUID) is generated for the request.
    *   A `TaskCompletionSource<ResponseMessage>` is created. This object is the key to the async magic. Its `Task` property is returned to the caller.
    *   The `TaskCompletionSource` is stored in a `ConcurrentDictionary` keyed by the `CorrelationId`.
    *   The `RequestMessage` is serialized to JSON and published to the server's predefined `request-queue`.
        *   **`ReplyTo` Property:** Set to the name of the client's unique reply queue.
        *   **`CorrelationId` Property:** Set to the generated unique ID.
    *   The `Task<ResponseMessage>` from the `TaskCompletionSource` is immediately returned to the client's application code.

3.  **Client Application Code (`Program.Main` in `RabbitMqClient.cs`):**
    *   Calls `SendRequestAsync` and gets the `Task<ResponseMessage>`.
    *   The client application can now perform other operations (e.g., `await Task.Delay(...)`, console output) without blocking because it only holds a `Task`, not the actual result.
    *   Later, it can `await` the `Task` to get the `ResponseMessage`. If the response has already arrived and the `TaskCompletionSource` was completed, `await` returns immediately. If not, it asynchronously waits.

4.  **Server Processing (`RabbitMqServer.Main`):**
    *   Receives the `RequestMessage` from `request-queue`.
    *   Extracts the `Payload`, `ReplyTo` queue name, and `CorrelationId` from the message properties.
    *   Processes the request (simulated by a `Thread.Sleep(1000)` in this example, representing work).
    *   Creates a `ResponseMessage`.
    *   Publishes the `ResponseMessage` (as JSON bytes) directly to the exchange "" (default direct exchange) with the `routingKey` being the `ReplyTo` queue name. The **same `CorrelationId`** is set on the response message's properties.

5.  **Client Receiving Response (Consumer's `Received` event in `RabbitMqRpcClient`):**
    *   The consumer listening on the client's unique reply queue receives the `ResponseMessage`.
    *   It extracts the `CorrelationId` from the response message's properties.
    *   It looks up and retrieves the `TaskCompletionSource` from the `ConcurrentDictionary` using this `CorrelationId`.
    *   If found, it calls `tcs.TrySetResult(responseMessage)` on the `TaskCompletionSource`, passing the received `ResponseMessage`. This action "completes" the `Task` that the client application code is holding (or awaiting).

6.  **Client Application Code (awaiting):**
    *   The `await` on the `Task<ResponseMessage>` (e.g., `ResponseMessage response1 = await responseTask1;`) completes.
    *   The client application receives the `ResponseMessage` from the server and can proceed with its logic.
    *   If the server doesn't respond within the timeout specified in `SendRequestAsync`, the `TaskCompletionSource` is cancelled, and the `await` will throw a `TaskCanceledException`.

This mechanism allows the client to make requests without waiting and efficiently receive responses when they arrive, correlating them back to the original requests, and handling potential timeouts.
